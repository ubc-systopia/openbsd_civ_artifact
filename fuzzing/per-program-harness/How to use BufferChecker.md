
This document explains how to use the BufferChecker library and provides a checklist for its usage.

BufferChecker provides two core functionalities:
1. PointerChecker for detecting pointer leaks
2. Necessary adaptations to make MSan fuzzing practical

For historical reasons, the outer directory of BufferChecker is still named `ptr_checker`. Time to use doublethink.
### 1. Obtain and Compile BufferChecker

```
cp -r /path/to/ptr_checker ./ptr_checker

cd ptr_checker

make
```

The above steps are all that's needed to compile `libbuffer_check.so`.

#### Understanding Build Parameters

There are only two relevant parameters that enable pointer checking and MSan checking:

```
# ENABLE_PTR_CHECK: Enable pointer leak detection
# Scans buffers for values that fall within process virtual memory regions
ENABLE_PTR_CHECK = 1

# ENABLE_MSAN_CHECK: Enable MemorySanitizer checks for uninitialized memory
# Requires linking with -fsanitize=memory for full functionality
ENABLE_MSAN_CHECK = 1
```

Please note that BufferChecker is a shared library, which means that if it is recompiled, it will affect all programs currently fuzzing with BufferChecker. If you need to use different build parameters for different programs, make separate copies of this library!

### 2. The Checklist

Here's the checklist I strongly recommend following when using this library:

```
1. Use tmux
  
2. Ensure you call ptr_check_skip on all messages generated by the fuzzer
  
3. Export the MSAN_OPTIONS: export MSAN_OPTIONS='handle_sigbus=0:exit_code=86:symbolize=0:exit_code=0'
  
4. Ensure you add -fsanitize-recover=memory in the program's Makefile (the target program's Makefile, not BufferChecker's)
  
5. Ensure you link libbuffer_check.so in the target program's Makefile: both (1) link it, and (2) use -Wl,-rpath to tell the dynamic linker where the .so is located
  
6. Don't forget to compile the program with MSan!
   
7. Also want to use UBSan? (Please do if the target has not been fuzzed with UBSan before)
   
8. Set AFL_PRELOAD to the BufferChecker library's location, e.g., `/opt/ptr_checker`
   
9. Dry-run the program with MSan enabled and verify that false positives do not hurt performance (they can make the program very slow!). If there are too many false positives, use `__attribute__((no_sanitize("memory")))` to suppress the warnings (usually, there are only a handful of functions that repetatively generating warnings, so this should not take very long)
```

### 3. Recommended Steps for Building Artifacts

MSan is incompatible with ASan, so the artifact should guide users to run two separate fuzzing campaigns: one with pointer detection and MSan, and one with ASan (you can decide which campaign includes UBSan).
 
Despite this, the artifact should provide a single codebase that includes all necessary modifications to enable the BufferChecker library (i.e., it should follow the checklist). When fuzzing without MSan, the artifact can guide users to edit BufferChecker's build parameters to disable both pointer checking and MSan options.

Although the artifact should follow the checklist, several steps can be safely omitted since they have already been incorporated into the source code on which the artifact is based. This includes checklist items that involve editing the source code: items 2, 4, and partially item 5 (more on this later), and 9.

However, since the location of the BufferChecker library in the environment reproducing the artifact may differ from the original development environment, and since the library location is hard-coded into the Makefile, you will likely encounter errors about `libbuffer_check.so` not being found. Instead of hard-coding the location, I recommend using an environment variable `BUFFER_CHECKER_ROOT` (please use this variable name for consistency) and referencing it as `$(BUFFER_CHECKER_ROOT)` in the Makefile to retrieve its value.
